# Sparkbase landing page

The Sparkbase landing page, release list and newsletter signup. It is one Next.js app (App Router, TypeScript): the pages, the API route and the database access all live here.

- `/`: landing page with the signup form
- `/privacy`: privacy notice
- `/unsubscribe?token=<uuid>`: unsubscribe page (the link opens a confirm step, and the button does the unsubscribe)
- `POST /api/subscribe`: signup endpoint
- `robots.txt`, `sitemap.xml`, Open Graph and Twitter images, and the icons are generated by the app

UI is built with [shadcn/ui](https://ui.shadcn.com) (Radix base, components in `components/ui`) and Tailwind CSS v4. Body text uses Inter, the wordmark uses Sora, and code uses JetBrains Mono.

Postgres is accessed with [postgres.js](https://github.com/porsager/postgres) and hand-written SQL. There is no ORM.

## Requirements

- Node.js 20.9 or later
- Postgres 13 or later (`gen_random_uuid()` comes from `pgcrypto`, which the migration enables)
- bun or npm. The lockfile is `bun.lock`, and every script also works with `npm run`.

## Local setup

```bash
bun install                 # or: npm install
cp .env.example .env.local  # then fill in the values
createdb sparkbase          # any empty database works
bun run migrate             # or: npm run migrate
bun run dev                 # http://localhost:3000
```

## Environment variables

| Name | Required | Notes |
| --- | --- | --- |
| `DATABASE_URL` | yes | Postgres connection string. Pooled (PgBouncer) URLs work because prepared statements are off. |
| `IP_HASH_SALT` | yes | Secret used to HMAC IP addresses for rate limiting. Raw IPs are never stored. Generate one with `openssl rand -hex 32`. If you change it, existing rate-limit rows stop matching, which is harmless. |
| `CONTACT_EMAIL` | yes in production | Shown on `/privacy` and `/unsubscribe`. A production build fails without it. |
| `NEXT_PUBLIC_SITE_URL` | yes | Public URL with no trailing slash, e.g. `https://sparkbase.io`. Used for metadata, the sitemap and robots.txt. |
| `NEXT_PUBLIC_GITHUB_URL` | no | Defaults to `https://github.com/shellhaki`. |
| `NEXT_PUBLIC_X_URL` | no | Defaults to `https://x.com/haki_xer`. |
| `NEXT_PUBLIC_PLAUSIBLE_DOMAIN` | no | When set, loads Plausible and sends one `signup` event with a `list` property. It also shows the Analytics section on `/privacy`. |

`NEXT_PUBLIC_*` values and `CONTACT_EMAIL` are read at build time, because the landing page and `/privacy` are prerendered. Rebuild after you change them.

## Database

`migrations/0001_init.sql` creates the `subscribers` and `rate_limits` tables. `npm run migrate` applies every migration file that has not run yet, in filename order, and records each one in a `schema_migrations` table. Running it again is safe.

The scripts read `DATABASE_URL` from the environment, or from `.env` and `.env.local` when those files exist.

### Exporting subscribers

```bash
npm run export -- --list waitlist > waitlist.csv
npm run export -- --list newsletter > newsletter.csv
```

The export includes only rows that have not unsubscribed. Columns: `email, list, source, unsubscribe_token, created_at`. Build unsubscribe links in your emails as `${NEXT_PUBLIC_SITE_URL}/unsubscribe?token=<unsubscribe_token>`. This project does not send email.

## How signup works

1. The form posts JSON to `/api/subscribe`. The body is `{ email, list, source?, website? }`.
2. The route rejects requests that are not same-origin with 403. It checks the `Origin` header against the host, and `Sec-Fetch-Site` when present.
3. The email is trimmed, lowercased and validated. Bad input gets 422.
4. If the `website` honeypot is filled, the route returns `{ ok: true }` and stores nothing.
5. The route counts the IP hash in a one-minute window in `rate_limits`. More than 5 requests in that window gets 429. Rows older than five minutes are deleted in the same request.
6. The route inserts the row with `on conflict (email, list) do nothing` and always returns `{ ok: true }`, so the response never shows whether an address was already on the list.

Email addresses are never logged. Errors are logged by Postgres error code only.

## Deploying

### Vercel

1. Import the repository.
2. Add the environment variables above for Production (and Preview if you use it).
3. Use a pooled connection string for `DATABASE_URL` when your provider offers one (Neon, Supabase, RDS Proxy and others).
4. Run `npm run migrate` once against the production database, from your machine or from CI.

### Any Node host

```bash
npm ci
npm run build
npm run migrate
npm run start   # listens on PORT, default 3000
```

Put the app behind a proxy that sets `X-Forwarded-For`. The rate limiter uses the first address in that header.

## Brand assets

- `public/brand/sparkbase-mark-source.png`: the original logo mark (transparent PNG)
- `public/brand/sparkbase-banner-source.png`: the original wordmark banner on black
- `public/brand/sparkbase-mark.png`: the mark cropped to its bounds, unchanged otherwise. The nav, `app/icon.png`, `app/apple-icon.png`, `app/favicon.ico` and the OG image are all generated from it.
- `assets/Sora-Bold.ttf`: the font used to render the OG image

The brand blue `#2D57FB` was sampled from the mark. It is defined once, as `--brand` in `app/globals.css`, and the shadcn `--primary` and `--ring` tokens point at it.
